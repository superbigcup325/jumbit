# Changelog

All user-visible changes to jumbit are recorded here, kept in step with the git
history. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/)
and the version numbers follow Semantic Versioning (SemVer).

## [Unreleased]

### Added
- One-line install script `scripts/install.sh`: platform detection (Linux x86_64 / macOS Apple Silicon; on Windows it points at the Releases zip) → download the matching release archive → install into `~/.local/bin` (`JUMBIT_INSTALL_DIR` picks another directory; `JUMBIT_VERSION` or a positional argument pins a version, defaulting to latest via the releases/latest 302 hop, with no API or jq dependency); POSIX sh compatible and usable as `curl | sh`; the release workflow distributes it as an asset, and README option 1 is rewritten from a manual download-and-unzip to a single command

### Changed
- Non-finite rank normalization moved up to the import entry point ([#3]): `add`/`import` (all three entry points — add/add_update/add_unchecked) now uniformly map `nan/-inf → 0.01`, `+inf/overflow → 9999999.99`, and clamp finite values to `[0.01, 9999999.99]`, with the rank constants promoted to core `pub` (RANK_MIN/RANK_MAX, a single source of truth shared with the encoding layer). Behaviour fix: previously `inf` was first poisoned into NaN by aging (total=inf → factor=0) and only then landed on 0.01 in the encoding layer, the opposite of the document's "inf clamps to the upper bound" and inconsistent with the hand-edited-database save path; every path now clamps per the documented rule, the aging total is healthy again (factors decay normally and other entries stop being wrongly purged)
- query no longer always writes to disk ([#2]): `sort_by_score` dropped an unconditional dirty flag (a display-only order is not a data change), and `load`'s legacy branch dropped the read-path `mark_dirty`; query now saves only when the filter chain really deletes something (a glob hit or a TTL expiry). Behaviour change: a read-only query no longer rewrites db.txt (upstream's query rewrites the file every time — a deliberate divergence here, aligning with this project's "read-only commands do not trigger a migration" promise, noted in USAGE's differences list); a legacy database is not migrated by a read-only query, and the first real data change (a write command or a lazy delete) converts it to plaintext with the content preserved; a query against a read-only data directory exits 0 (it used to hit EACCES on "save even without changes" and report could not save with exit 1)

- Error wording closed out (aligning with 0.1.3's established rule — the uniform `jumbit: ` prefix and full English — for the gaps a blackbox diff against real zoxide 0.10.0 turned up, [#1]; breaking: scripts and agents that parse stderr must follow):
  - added the `jumbit: ` prefix (upstream carries `zoxide: ` in each case, verified one by one): `not a directory` / `path not found in database` (in remove/describe/edit) / `current database is not empty, specify --merge to continue anyway` / `you are already in the only match` / `could not find fzf, is it installed?` / `could not read selection from fzf`
  - the same pass prefixed jumbit's extensions and the one-liners: `could not read <path>` / ``failed to run `atuin` `` (import), `path already in database` / `no editor: set $EDITOR or $VISUAL` / `editor exited with code N` (edit)
  - config-layer Chinese wording turned into English, with the prefix: `_JB_DATA_DIR must be an absolute path` / `cannot determine the data directory: set _JB_DATA_DIR` / `invalid glob in _JB_EXCLUDE_DIRS` / `_JB_MAXAGE must be a non-negative integer` / `could not find home directory`
  - deliberately left unprefixed (that is upstream's own wording, noted in USAGE's differences list): `fzf returned an error` / `fzf was terminated` / `fzf returned an unknown error`
- Main package renamed `cmd/main` → `cmd/jumbit`: the mooncakes install command becomes `moon install superbigcup325/jumbit/cmd/jumbit`, and the binary lands as `~/.moon/bin/jumbit`, matching the executable name, with no manual rename needed (the old install command `.../cmd/main` stays frozen at 0.1.3 because a registry version cannot be overwritten)
- query load decode fast path: when a plaintext db.txt line matches the shape the encoder produces (a plain-digit timestamp, an integer or exactly-two-decimal fixed-point rank, values ≤ 2^53) the whole-line UTF-8 decode and `parse_f64` are skipped (fixed-point is assembled from integers with a single IEEE division, bit-identical to `parse_f64`); any irregular shape (sign, exponent, inf, nan, out of range, other whitespace) falls back to the original slow path wholesale, with zero change in error wording or precedence. On the million-line stress domain (270k entries) a keyword query went 0.193 → 0.135s and a full listing 0.277 → 0.219s, the ratios against upstream 11x → 6.8x / 2.0x → 1.6x; function-level decoding is about 5x (moon bench codec round-trip 5.06 → 2.82ms per 10k). Equivalence is pinned by a new whitebox comparison suite (fast and slow path case by case + an assertion that the writer shape is hit + the whole routing chain), and the existing quickcheck round-trip properties now cover the fast path too
- Second round of query hot-path work: keyword matching allocates nothing for normalization (`to_lower` doing ASCII-only folding became an ASCII uppercase pre-scan, which allocates nothing when there is no uppercase, and keyword folding is hoisted to once per query) and sorting moved after filtering (filter first, sort after, so miss-type queries skip the full sort; tied scores keep their in-database relative order, identical to sort-then-filter). The `--fuzzy` fallback became single-pass (`StreamOptions` gained a `fuzzy_superset` collection point, replacing the empty-keyword re-run of the whole filter chain; the glob/TTL lazy-delete set is unchanged and ordinary queries pay nothing). On the million-line stress domain (270k entries) a keyword query went 0.135 → 0.060s (6.8x → 3.2x against upstream), the `--fuzzy` fallback miss 0.22 → 0.12s, and a full listing 0.219 → 0.210s; perf_check gained a fuzzy-fallback guard scene

### Documentation
- BENCHMARKS.md re-measured end to end (2026-10-05, the build after the fast path landed): the previous numbers were still from the 09-13 binary-format build (the benchmark had not been re-run since the plaintext format and the lexicographic comparator landed, leaving the query rows off by up to 2.5x). The margin analysis is rewritten to the current truth (queries are dominated by the plaintext decode; import by the dedup sort + lex comparator + plaintext encoding), and the [#3] divergence is noted (about 2% entry-count difference on the stress domain, with the dataset_check semantic comparison 19/19 green)
- perf_check.sh guard fixed: removed a false alarm that ran `wc -l` on upstream's binary database (7317 = newline bytes in binary content); the two sides' entry-count assertion changed from equality to a 5% tolerance band (the [#3] divergence), with catastrophic purging still caught by an 80%-floor check
- USAGE's "Differences from zoxide" gained five previously unrecorded divergences found by a blackbox diff against real zoxide 0.10.0 ([#4]): a repeated `--exclude` lets the last one win (upstream errors with exit 2), an interactive keyword miss does not start fzf (upstream starts it first), jumbit's fzf argv lacks upstream's `--bind` group, `help <unknown subcommand>` prints the general help and exits 0, and a read-only query does not rewrite the database file (upstream rewrites on every save); the fzf spawn-failure wording was given the `jumbit: ` prefix in the same pass

### Fixed
- Sandbox leak in edit's "EDITOR containing a space is split on the command line" test case ([#5]): the fake editor took the database file with `"$1"`, but after the split the editor's own flag (the `--quiet` in the case) took `$1`, so the content was appended to a same-named file in the process's cwd (that is where the `--quiet` left in the repository root came from, regenerated on every `moon test`); the fake editor now takes the last argument and writes the real database file

### Removed
- The `--quiet` left in the repository root was a local artefact of that test leak (never under version control) and is no longer produced now that it is fixed; `docs/declaration.md`, wrongly assumed to be tracked when this was filed, is in fact an untracked local file (the whole docs/ directory is out of the repository), so there was nothing to clean up on the version-control side

## [0.1.3] - 2026-09-30

### Added
- `--version` / `-V`: print the version line and exit 0 (matching upstream's clap top level); a no-argument invocation now writes the full help to stderr and exits 2 (matching upstream's no-subcommand invocation; breaking: a script relying on the old "no arguments shows help, exit 0" must use `jumbit help`); `init`'s flags and the shell argument may be interleaved freely (`jumbit init --cmd zz bash` is valid, matching clap's intermix semantics; breaking: an invocation shape that used to report "unsupported shell" now works as expected)
- macOS support (Apple Silicon): the CI matrix grew to ubuntu/macos and runs for real (darwin-aarch64), with 280 tests, smoke, golden and the MCP byte surface showing no divergence from Linux; Intel macs are unsupported (the toolchain's official install script has no darwin-x86_64 branch)
- Windows support (x64): the CI probe is fully green (288 tests / the whole smoke chain / the golden byte surface); path resolution follows the platform's component model (drive letters and double separators, matching upstream's Windows branch), and keyword and glob separator handling is platform-aware (glob patterns use forward slashes, where `/` matches a `\` path); moonbitlang/async was bumped to 0.22.4 (`mkdir allow_exist` closes a directory-creation race); the collision between `_JB_EXCLUDE_DIRS`'s colon separator and drive-letter colons is a known limitation

### Changed
- **User-visible wording is now entirely English** (breaking: scripts and agents that parse stderr must follow): aligning with upstream zoxide's message surface — runtime errors (exit 1) uniformly carry the `jumbit: ` prefix (matching upstream's `zoxide: `), and a query miss and an empty database merged into `jumbit: no match found` (upstream's wording; the two cases are no longer distinguished and the keyword is no longer echoed); usage errors (exit 2) follow the clap idiom: `error: unrecognized subcommand '<X>'` / `error: invalid value '<X>' for '<FLAG>'` (with a `[possible values: ...]` line) / `error: a value is required for '<FLAG>' but none was supplied` / `error: the argument '<A>' cannot be used with '<B>'`, ending with `For more information, try 'jumbit help'.`; `jumbit help` was rewritten in English; `export --agents`'s header comment and column names became English (`| Path | Description |`, changing what gets pasted into AGENTS.md); `status`'s human-readable labels became English (`data file`/`file size`/`format`/`entries`/`notes`/`aging threshold`/`existing`); messages already byte-frozen with upstream, such as import's `file:line: invalid entry` and `current database is not empty...`, were left untouched. Decision on record: a bilingual or environment-variable-switched surface is not planned (upstream and comparable tools have no precedent, and a dual wording table violates the single source of truth); the Chinese wording remains in the git history (before 80e3f1c) and will be revisited if users ask
- `_JB_EXCLUDE_DIRS`'s glob wildcards now match the upstream glob crate's default semantics (require_literal_separator=false, verified at the source level): `*` and `**` cross separators matching any sequence, and `?` and `[...]` match any single character including separators. The earlier documented claim that "`*` semantics are aligned" did not match the implementation (natural patterns like `*/backend*` silently failed); `{a,b}` is still literal (a retained difference from upstream); case sensitivity and whole-path anchoring are unchanged (breaking: patterns relying on the old "does not cross separators" behaviour need rewriting)
- MCP `jumbit_query`'s `keywords` is a required argument: when it is missing from `tools/call` the call goes through the protocol layer as -32602 (matching the inputSchema `required` and the tool-registration draft), instead of silently running "no keywords = highest score"; the schema description dropped the untrue "Omit to list all entries" (the real behaviour was never a full listing) (breaking: MCP clients relying on the default must pass keywords explicitly)
- Windows phase-2 follow-ups: under async 0.22.4 the win32 glob assertions were promoted (the `C:/*` cross-separator open question dissolves under the new glob semantics), smoke's tcsh/xonsh real-load gates were fixed, together with dead code in the nushell/posix/powershell branches

## [0.1.2] - 2026-09-23

### Added
- The `edit` subcommand (a jumbit extension, no upstream counterpart): with no flags it edits the plaintext database with `$VISUAL`/`$EDITOR` (falling back to `vi`), validates every line on read-back, and refuses to save a bad line, reporting its line number; `--rename <old> <new>` changes a path (the human annotation follows, and hitting an existing path reports `path already in database` rather than merging); `--prune` drops entries that no longer exist and lists them line by line. The three forms are mutually exclusive. Upstream's current `edit` is fzf-driven rank adjustment (announced for removal), which jumbit does not follow
- The plaintext database `db.txt` (following the plaintext direction of upstream [zoxide#1288](https://github.com/ajeetdsouza/zoxide/pull/1288), which jumbit got to before that PR merged): one `timestamp\trank\tpath` per line, readable and hand-editable with any text tool, with a bad line making the whole database refuse to load and reporting its line number (up to 8 lines, then `... and N more`); human annotations moved to the side file `notes.tsv` (`path\tnote`), leaving the main format interchangeable with upstream's plaintext

### Changed
- **Storage format migration**: `db.zo` (binary) → `db.txt` (plaintext). An old database converts automatically on the first write (read-only commands do not trigger it), the original `db.zo` is kept afterwards and can be deleted by hand. Pathological data is repaired during migration: a `NaN` rank goes to the lowest weight (0.01), an out-of-range rank clamps to [0.01, 9999999.99], and an empty-path entry is dropped (the plaintext line format cannot express it)
- `status --json`'s `format_version` (integer) key was renamed to `format`, whose value is a format-identifying string: `"plaintext"` / `"binary"` (an unmigrated old database) / `null` (no database); the corresponding human-readable row became "format" (breaking; consumers must follow)
- `describe --note` rejects tabs (annotations persist in the TSV side file, where a tab is the column separator), with the wording `note cannot contain newline or tab`
- Non-finite rank behaviour changed: reading a `nan` rank line makes the whole database refuse to load (reporting the line), and on import `inf` clamps to the upper bound while `nan` goes to 0.01; upstream 0.10.0's "non-finite poison" problem ([zoxide#1280](https://github.com/ajeetdsouza/zoxide/pull/1280)) no longer applies under the plaintext format, retiring the "known issue" carried in 0.1.0

## [0.1.1] - 2026-09-22

### Added
- `mcp`: a stdio MCP server (a jumbit extension, no upstream counterpart): newline-delimited JSON-RPC 2.0 (MCP stdio transport, version negotiation supporting 2024-11-05/2025-03-26/2025-06-18: echo a supported version, otherwise answer 2025-06-18); two tools, `jumbit_query` (keywords/fuzzy/limit, executing from the same source and producing the same bytes as `query --json`) and `jumbit_export_agents` (the same as `export --agents`); an `initialize` response carrying server instructions (the short narrative of when to reach for jumbit); the error split matching comparable implementations (atuin mcp), with an unknown tool or a malformed argument going through the protocol layer as -32602 and an execution failure such as a miss becoming `isError: true` in the result (same wording as the CLI's stderr); notifications are never answered, and closing stdin exits cleanly with 0. The protocol's bytes are frozen by `scripts/mcp_check.sh` (a new CI step), and real-client compatibility was tested against the official TypeScript SDK (handshake / tools/list / both tool calls / the error split)
- `status`: a database self-check command (a jumbit extension, no upstream counterpart): by default it quickly reports the data file path, its size, the actual format version (read from the file header), the entry count, the note count and the current `_JB_MAXAGE`; `--check` explicitly runs the O(N) existence scan and appends `existing K/N`; `--json` prints a single-line object with a fixed key order (the agent channel); a corrupt database exits 1 and reports `数据文件损坏: <cause>`, while an empty database (no db.zo) is reported as zeros. The human and JSON surfaces are covered by goldens (including normalization of a random data-directory path)
- The shell integration templates grew to all nine shells (matching upstream): elvish / nushell / posix / powershell / tcsh / xonsh were added, and `jumbit init <shell>`'s argument matrix and syntax gates (elvish compile, nu-check, sh -n, pwsh parse, tcsh -n, py_compile) were all verified on real machines

### Changed
- Toolchain pin bumped `0.1.20260904` → `0.1.20260920` (moonc v0.10.13 → v0.10.14): `bytes.view` migrated to `exact_view` (a strict-slicing rename with zero semantic change); under the new unused_package lint (which judges main-block imports by the main code only) test-only dependencies moved into `for "test"`/`for "wbtest"` blocks (in cli/cmd/main/core/platform/templates), and the unused `moonbitlang/async/io` import was dropped repository-wide; under the implicit_impl_as_method lint, 15 public types' derived-method lifts are now explicitly suppressed by each package's `extends.mbt` (the `.mbti` files are byte-identical before and after `moon info`, so the public surface is unchanged); 59 blackbox test references to the package under test gained the `@pkg.fn` qualifier; the dataset/chaos/realdata/golden/mcp byte surfaces are all green and performance is the same order of magnitude
- The help environment-variable table gained `_JB_FZF_OPTS` (extra arguments passed through to fzf), which the README table already documented but `jumbit help` had left out
- import/query memory and allocation work (behaviour and output bytes unchanged): bad-row messages and line-locating strings are built lazily, the db encoding is pre-sized, `--tsv` output is streamed, stderr is written in batches, and import became a single streaming pass (matching upstream's lazy iterator structure in import.rs::run, parsing and importing each line of the six plugins' file sources through a callback, with atuin folding kept materialized): a million-line import dropped peak memory 499→203MB and time 2.29→1.62s, and a full `--tsv` output dropped its peak 217→85MB

### Documentation

- The README was restructured into a project-introduction surface (why / features / install / quick start / minimal command set / documentation navigation): the full command and flag tables, the shell-integration options, the agent channels, tool integrations, the six-plugin import, the frecency/aging/matching semantics, the environment variables and the differences list moved into the new USAGE.md; the exit-code table, the symptom lookup, the stderr message reference (measured one by one in a blackbox) and corrupt-database recovery became the standalone TROUBLESHOOTING.md; the import documentation gained a per-plugin data-format column
- An English README_EN.md was added, mirroring the Chinese version section by section

### Fixed
- A divergence from upstream in the database's entry order: `sort_by_path` wrongly used MoonBit's `String::compare` (shortlex, length first), so on mixed-length path sets the entry order differed from upstream Rust's `path.cmp` (pure lexicographic); it now uses an explicit pure lexicographic comparison (code-unit first, a prefix sorting before the longer string). This affected the entry arrangement in db.zo after an import or a write and the tie order of a query when scores are equal, while the entry multiset is unchanged; importing the same dataset with both tools and comparing the parsed output pinned the first entry as identical, and a locking test case was added (a red-verification for shortlex misordering)
- User-facing error wording cleaned up, so Debug enum names and Repr structures no longer leak: `could not read <path>: <errno phrase> (os error N)` (was the `<@os_error.OSError: …>` debug structure), `数据文件损坏: <short Chinese sentence>` (was an enum name such as `UnsupportedVersion(1651663207)`), and `打开数据库失败: <short Chinese sentence>` (was `Codec(CorruptedData)`); a re-audit caught the same family's leftovers: save failure `保存数据库失败: 读写失败: …`, `_JB_RESOLVE_SYMLINKS` realpath failure `解析路径失败: <path>: …`, and status's file-read failure `无法读取数据文件: …` (errno phrases go through OSError's public predicates covering ENOENT/EACCES/ENOTDIR/EEXIST, with everything else keeping the `(os error N)` numeric suffix, since `errno_to_string` is marked alert_internal and unusable); the golden status-corrupt.err was re-frozen alongside
- `query --interactive`'s fzf lookup now resolves PATH ahead of the spawn (taking the first candidate that is both a regular file and executable): when a bare name hit a non-executable file or a same-named directory, the old implementation left the exec failure to the child's wait exit code, reporting `fzf returned an error` with a leaked child stderr (measured in a blackbox as `inappropriate ioctl for device`), contradicting the rule that a spawn failure uniformly reports `could not find fzf, is it installed?`; it is now uniformly NotFound (exit 1), and a non-executable candidate is skipped in favour of a later executable one
- CLI parsing supports the `--flag=value` form (matching upstream clap's two forms): `init --cmd=`/`--hook=`, `query --exclude=`/`--limit=`, `add --score=`, `describe --note=`. The `--cmd=cd` form documented in the README had actually been rejected (exit 2, "unknown command"); the equals form of boolean and unknown flags still reports the original wording with exit 2, and nothing after `--` is split
- `query --interactive` aligned with upstream zoxide 0.10.0 (measured with a fake-fzf probe matrix): the selection output no longer appends an extra newline (the old `println` added one); an fzf selection shorter than 7 bytes now takes the error path `could not read selection from fzf` (exit 1, where the old code printed an empty line and exited 0); an abnormal fzf exit code is now mapped to upstream's semantics instead of passed through: 2 reports `fzf returned an error`, 128..=254 and a signal kill report `fzf was terminated`, and everything else (3..=127, 255) reports `fzf returned an unknown error`, all with exit 1; 130 (a user interrupt) is still passed through silently
- Feeding fzf its candidates no longer aborts the command on a broken pipe when fzf exits early (matching upstream's write handling, where BrokenPipe → wait means the feeding stops silently)
- A shell invoking jumbit by bare name through PATH reported "unknown command: jumbit": argv[0] handling changed from "strip only when it contains a `/`" to stripping unconditionally (matching upstream's clap convention that the first argument is the bin name). The old heuristic assumed `moon run` does not pass a program name, but with the pinned toolchain (moon 0.1.20260904) `moon run` passes the exe/wasm path for both native and wasm, and running the binary from the OS passes a bare name or a full path, so argv[0] is a program name on every startup path; the old logic took the program name for a subcommand under bash/zsh/fish bare-name invocation (exit 2), which made the hook's automatic recording fail silently

## [0.1.0] - 2026-09-11

### Added
- Dataset comparison tooling: `scripts/gen_dataset.py` (path-pool sampling + a Zipf visit distribution + time decay + boundary rows, fixed-seed and reproducible) and `scripts/dataset_check.sh` (eight scenes — the six import plugins / aging / --merge — diffed against real zoxide 0.10.0, including sort correctness, exit codes and a byte-for-byte stderr comparison of bad rows)

- `query --json`: a single-line JSON array of every match (path/score/last_accessed/matched_by), the structured channel for scripts and agents, mutually exclusive with `--interactive`
- `query --tsv`: headerless tab-separated data rows (`path\tscore\tlast_accessed\tmatched_by`, the same column order as the `--json` keys), with the path written verbatim and unescaped; NaN/±Infinity come out as the literals `NaN`/`Infinity`/`-Infinity`; mutually exclusive with `--json`/`--interactive`, and combined with `--list` the `--list` wins (existing precedent)
- `query --limit <n>`: a uniform truncation for the list-shaped `--list`/`--json`/`--tsv` outputs, taking the first n after sorting; `--limit 0` gives empty output with exit code 0 and does not trigger the no-match error path; combining it with the single-result path or `--interactive` reports an argument error
- `query --fuzzy`: the fallback when an exact pass finds nothing — a row matches when each keyword (ASCII-folded) is a substring of some path component, with no anchoring on the final component, order-free and allowing the same component; `--json`'s `matched_by` carries the two values `exact`/`fuzzy`, annotating the source of the evidence
- `import <plugin>`: import history from other tools, supporting `atuin`/`autojump`/`fasd`/`z`/`z.lua`/`zsh-z` (matching upstream's cmd/import.rs plus the six modules under import/)
  - Pour directly into an empty database; a non-empty one requires `--merge` (allowed before or after the plugin name, upstream's global-flag semantics)
  - Data files are probed by each plugin's standard convention (`_Z_DATA`/`_FASD_DATA`/`ZSHZ_DATA`/`_ZL_DATA`/`XDG_DATA_HOME`); z.lua falls back to the fish variant's path when the main one is missing; atuin is read through the `atuin history list --print0` subprocess
  - autojump's rank is sigmoid-normalized (last_accessed=0); atuin's UTC timestamps are parsed to epoch (rank=1.0, with consecutive records in the same directory folded)
  - Bad rows are reported one by one as `<file>:<line>: <reason>` without aborting (atuin says `line N`); when the import finishes, dedup + age(maxage) runs before the save
- The glob matcher: `*`/`?`/`[...]`/`[!...]` never cross path separators, `\` escapes, and an invalid pattern (unterminated / empty class / reversed range / trailing escape) is an error; `{a,b}` is unsupported (a difference from upstream)
- Data layer: the three-field `Dir` model (path/rank/last_accessed) and frecency score decay (<1h ×4.0 / <1d ×2.0 / <1w ×0.5 / else ×0.25)
- Database operations: weight accumulation (add/add_update, with a negative delta clamped to 0), sorting by score, and a dirty flag
- A jumbit-owned binary persistence format (a 4-byte version number + length-prefixed entries), a 32MiB cap, and explicit errors for malformed data (truncation / version mismatch / invalid UTF-8 / over the cap)
- db v2: a trailing note annotation per entry (`Dir::note`, encoded as no-annotation when the length is 0), with v1 databases read compatibly and no migration; `Database::set_note` sets or clears it and marks dirty; when dedup merges, a note on either side is kept
- `describe <path> [--note text]`: set, clear (`--note ""`) or display the human annotation on a recorded entry; annotations reject newlines; the path uses the same dual attempt as remove (the original string, then the normalized form)
- `export --agents`: annotated entries are printed in frecency-descending order as a Markdown "project map" (two columns, path and description, with `|` escaped to keep the table intact), ready to append to AGENTS.md so a coding agent can learn the workspace; it does no existence check (an offline view), and an empty database prints an empty header
- Atomic write: a tmp file (a random name from system entropy, retried 5 times on collision) + a sync flush + a rename replacement, with automatic cleanup on failure
- Data-directory resolution: `_JB_DATA_DIR` (which must be an absolute path) first, falling back to `$HOME/.local/share/jumbit`
- Project scaffolding: laid out with `moon new`, `preferred_target = "native"`, the MIT license, and a package structure layered as `core` (the pure-function kernel) / `platform` (the IO shell) / `config` / `cli`
- The pinned dependency `moonbitlang/async@0.21.2`: its `fs` subpackage provides file reads and writes with a synchronous flush plus `rename` (the basis of the atomic write), and its `process` subpackage provides subprocess invocation (the basis of interactive selection)

- Keyword queries: the last keyword anchors the path's final component and the preceding ones are consumed right-to-left without overlapping (matching zoxide's matching semantics, with ASCII-only case folding)
- The query filter chain: score sort → keyword → base_dir (component-level prefix) → exclude glob (a hit lazily deletes) → exists check (last) → lazy deletion for a missing directory older than the 3-month TTL; the exists callback is injected so the chain is purely testable
- Database deletion: remove by path, with an O(1) swap_remove (the lazy deletion persisted)
- The `jumbit` command-line entry: `add <path>...` records directories (path normalization, newline and non-directory validation); `query [kw]...` filters by keyword and prints the highest-scoring directory; `query --list` (every match, descending by score); `--score` (a 6.1f score prefix); `--all` (skip the existence check); `--exclude <path>` (exact-path exclusion, with an explicit error when it excludes the only match)
- Environment variables `_JB_EXCLUDE_DIRS` (colon-separated globs, a hit lazily deletes, defaulting to excluding the home directory itself), `_JB_RESOLVE_SYMLINKS=1` (resolve symlinks on add, and never follow them in reverse on query) and `_JB_MAXAGE` (the aging threshold for the database's total score, 10000 by default, with an error on an invalid value)
- `remove <path>...`: delete by the original string and the normalized path, with both attempts and an explicit error when neither is found
- fzf interactive selection: `query --interactive` feeds the entries to fzf by score (with an explicit error when fzf is missing), and `_JB_FZF_OPTS` passes custom arguments through via FZF_DEFAULT_OPTS
- The project README: how to build, the full usage, the shell integration, the environment-variable table, the differences from zoxide, and the license
- Shell integration: `jumbit init bash|zsh|fish` emits an integration script (`--cmd C` for a custom command name, `--hook pwd|prompt|none` for the trigger, `--no-cmd` to define no alias), with the script's `_JB_ECHO`/`_JB_RESOLVE_SYMLINKS` taking effect at runtime
- `add --score N`: set this visit's incremental weight
- The add chain aligned with upstream: a path containing a newline and a path hitting an exclude glob are skipped silently, a non-directory aborts immediately, and aging by total score runs before the write
- The debug echo `_JB_ECHO=1`: echo the recorded directory on add
- The end-to-end smoke script `scripts/smoke.sh`: verify add→query echoing and error exit codes against the real binary
- The developer regression script `scripts/regression.sh`: four gates — `moon check --deny-warn`, `moon test`, `moon fmt --check` and the `moon info` interface freeze — any of which failing exits non-zero

### Fixed

- Score display on an exact half-boundary (e.g. a stale entry at 1.0×0.25=0.25) now rounds half-to-even as Rust's `{:.1}` does, so the `--score` prefix is byte-identical to upstream (`.round()` used to round half away from zero, showing 0.25 as 0.3)
- Persistence decoding rejects a database file whose path bytes contain NUL or a newline (the add entry point already blocked those, but a hand-built database file could slip past)

### Known issues

- Non-finite rank poisoning (inherited from upstream 0.10.0, byte-identical in a Linux probe against real zoxide on 2026-09-10): `import` (the z family and autojump; atuin's rank is always 1.0 so it is unaffected) accepts `inf`/`nan` literals and large numbers that overflow-saturate to inf such as `1e309` (Rust's `f64::from_str` semantics), and `add --score` accepts them too. The consequences: with `total=inf`, `age()` zeroes the factor and purges every other entry in the database (rank < 1) while the NaN entry survives; `total=NaN` makes `total > max_age` permanently false, so aging stops forever; the whole run exits 0 with no warning. Upstream's fix [ajeetdsouza/zoxide#1280](https://github.com/ajeetdsouza/zoxide/pull/1280) is an open, unmerged PR; when it merges jumbit will follow (rejecting non-finite ranks on import and reporting the line). **Postscript (0.1.2): the plaintext format migration built the fix in** — see the Unreleased Changed section; this problem no longer applies under db.txt

### Internal

- Database encapsulation tightened: the fields became impossible to construct or mutate from outside, and `all()` returns a copy of the array, guaranteeing the dirty flag stays consistent
